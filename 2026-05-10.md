4. Problemas encontrados
   a. GoDaddy bloquea registros A en `www` con leyenda "No se puede eliminar / editar" cuando hay reenvío de dominio activo. El reenvío hay que desactivarlo desde `?tab=forwarding`, no desde el panel DNS. Para `admira.tv` y `admira.app` se desactivó y se pudieron meter los registros. Para `admira.store` el usuario aún no liberó el reenvío, por eso `www.admira.store` sigue apuntando a las IPs ghost.
   b. `csilvasantin.github.io` no se puede "deactivar" Pages (es el repo `<user>.github.io`) — la operación `DELETE repos/.../pages` da `"Deactivating GitHub pages for this repository is not allowed" (HTTP 422)`. La salida fue limpiar solo el `cname` con `PUT` y body `{"cname":null}` vía `--input -`, no con `-f` (que no permite null).
   c. El cert HTTPS de `admira.tv` se quedó atascado >1h sin emitirse pese a tener DNS correcto, sin CAA, y con cert de `admira.app` aprobado en minutos. Se desbloqueó con el patrón nudge (clear cname → wait 30s → set again).
   d. El sitio OmniPublicity llama a `https://omnipublicity-api.csilvasantin.workers.dev` (Cloudflare Worker). Si el worker tiene `Access-Control-Allow-Origin` hardcoded a `csilvasantin.github.io`, el portal en `admira.app` cargará el mapa MapLibre pero no las pujas en vivo. Verificación pendiente.
   e. El JS `home-agibot.js` original de `admira-bots` tenía toda la i18n EN/ES con strings Agibot. Se borró del fork en `admira-store` junto con el toggle de idioma para no embarrar el v1; queda pendiente reescribir si se quiere ENG.
